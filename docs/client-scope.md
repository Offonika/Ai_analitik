# AI-аналитик отчетов: пилот Шумейко WB/1C

Этот документ — простая версия scope для согласования с заказчиком «Шумейко и
партнеры». Полный технический состав текущего Excel MVP зафиксирован в accepted
implementation spec. Если короткий клиентский scope и accepted spec расходятся,
для реализации используется accepted spec.

Документ описывает клиентскую Excel-передачу пилота. DB-first публикация,
авторизованный web-кабинет и source refresh являются внутренним контуром сборки и
эксплуатации, пока клиенту отдельно не согласован web-доступ.

# Коротко

Пилот проверяет продуктовую рамку `AI-аналитик отчетов`: сервис собирает
read-only данные, считает показатели, помогает консультанту увидеть проблемы и
подготовить клиентский аналитический отчет.

На первом этапе делаем Excel-отчет за согласованный период отчета. Период отчета
задается бизнес-задачей или конкретным `report_run`, а не просто тем, какие даты
пришли из WB/1С.

Фактически загруженные WB/1С данные показываются как покрытие источников. Если
источники закрывают выбранный период не полностью, отчет явно показывает статус
ограничения и не заменяет недостающие даты нулями.

Текущий опубликованный baseline использует период `2026-03-01` — `2026-06-17`.

Коммерческий период для финальной приемки можно согласовать отдельно, например
как 2 квартал 2026, если WB и 1С источники будут загружены за полный квартал.

Параметры текущего MVP:

- 1 клиент;
- 2 организации в 1С;
- 2 кабинета Wildberries;
- схема WB: FBO и FBS;
- финансовый факт берем из WB Finance / Financial Reports;
- себестоимость берем из `1С:УНФ`, включая уже распределенные допрасходы;
- маппинг WB и 1С берем из 1С или согласованной выгрузки;
- эквайринг включаем в расчет;
- НДС 5% внутри цены и УСН 1% показываем отдельным налоговым слоем;
- рекламу переносим на следующий этап;
- web-кабинет и регулярный мониторинг используются как внутренний контур
  публикации/эксплуатации и передаются клиенту только после отдельного
  согласования доступа.

Главная цель — показать клиенту прибыльность товаров после комиссий, логистики,
хранения, приемки, удержаний, эквайринга, возвратов и себестоимости.

# Что получает клиент

Клиент получает Excel-файл, где видно:

- общую прибыльность за период;
- результат по двум организациям 1С;
- результат по двум кабинетам WB;
- прибыль и маржинальность по товарам;
- недельную динамику;
- расходы WB;
- себестоимость с уже распределенными допрасходами;
- товары без маппинга или себестоимости;
- неполные данные, которые нельзя считать точным фактом.

# Первый Excel MVP

Обязательные листы:

- `README`;
- `Дашборд`;
- `Сводка`;
- `Сводка по организациям`;
- `Сводка по кабинетам WB`;
- `Юнит экономика`;
- `Товары`;
- `Динамика`;
- `Сводный отчет WB`;
- `Сверка по отчетам WB`;
- `Сверка с 1С`;
- `Сверка с 1С ОПиУ`;
- `Валовая прибыль 1С`;
- `Сверка услуг WB`;
- `Расшифровка услуг 1С`;
- `Распределение расходов`;
- `Товары по отчетам 1С`;
- `Расходы WB`;
- `Возвраты`;
- `Упущенные продажи`;
- `Себестоимость 1С`;
- `Маппинг`;
- `Ошибки данных`;
- `Методика`.

Опциональный лист:

- `ИИ-резюме`.

Отдельный AI-черновик клиентского отчета может готовиться для консультанта на
основе рассчитанных фактов. Консультант проверяет его перед передачей клиенту.

Для клиента по умолчанию видны основные вкладки: `Дашборд`,
`Юнит экономика`, `Возвраты`, `Ошибки данных` и `Методика`. Остальные листы
остаются в файле как технические и сверочные.

Недельная динамика строится по неделям понедельник-воскресенье в timezone
`Europe/Moscow`. Если отчет строится до окончания квартала, он считается
промежуточным.

# Как считаем прибыль

```text
прибыль =
  выручка
  - комиссия WB
  - логистика
  - хранение
  - приемка
  - удержания, штрафы и доплаты
  - эквайринг
  - себестоимость 1С с уже распределенными допрасходами
```

Дополнительно считаются НДС 5% внутри цены и УСН 1% от выручки. В отчете
показывается прибыль до налогов и прибыль после налогов.

Возвраты относятся к периоду WB Finance. Реклама не вычитается из прибыли первого
MVP и показывается как не включенная в расчет.

# Подключение к 1С

Формат доступа к 1С пока не выбран. Возможные варианты:

- OData;
- HTTP-сервис 1С;
- регламентная выгрузка;
- SQL read-only на индивидуальном сервере.

На первом техническом контуре можно использовать согласованную обезличенную
выгрузку. В любом варианте сервис работает только на чтение и не меняет данные
1С.

# Что не входит в первый этап

- запись в WB или 1С;
- рекламная аналитика;
- самостоятельный клиентский web-доступ без отдельного согласования;
- уведомления;
- production-хранение клиентских данных;
- подключение других маркетплейсов;
- налоговые, юридические или бухгалтерские выводы вместо специалиста.

# Критерии приемки

Первый этап успешен, если:

- отчет построен за согласованный период отчета; текущий опубликованный
  baseline использует `2026-03-01` — `2026-06-17`;
- покрытие источников WB/1С явно показано; если оно неполное, отчет имеет
  видимый статус ограничения;
- учтены 2 WB кабинета и 2 организации 1С;
- поддержаны FBO и FBS;
- эквайринг включен в прибыль или отчет помечен как неполный;
- налоговый слой НДС 5% и УСН 1% показан отдельно;
- реклама не влияет на прибыль MVP;
- ошибки данных видны отдельным листом;
- сводки сходятся с расчетной витриной;
- повторный расчет на тех же данных дает тот же результат;
- сервис не меняет данные в Wildberries и 1С.

# После Excel

После 2-3 циклов отчетности можно проектировать:

1. внутренний кабинет консультанта;
2. клиентский web-кабинет;
3. мониторинг свежести источников, уведомления и регулярные digest;
4. рекламную аналитику.
