> **Устаревший документ.** Рабочий процесс заменен собственным сервисом
> сопоставления: `docs/specs/marketplace-1c-mapping-service.md`. Расширение 1С
> может использоваться только как read-only импорт кандидатов.

# Назначение

Этот runbook описывает, как собрать и поставить клиентское расширение 1С
`offonika_<version>.cfe`.

Расширение добавляет только read-only HTTP-сервис для чтения сопоставления
маркетплейсов и 1С из уже установленного расширения `ИС_Маркетплейс`. Оно не
пишет в 1С, не читает токены или профили API и не содержит секретов.

# Что должно быть у клиента

Перед установкой:

- рабочая или тестовая база `1С:УНФ`;
- установленное и активное расширение `ИС_Маркетплейс`;
- заполненная форма сопоставления товаров WB и/или Ozon с 1С;
- возможность установить дополнительное расширение `.cfe`;
- возможность опубликовать HTTP-сервис 1С;
- отдельный пользователь 1С только на чтение.

# Артефакт

Имя расширения:

```text
offonika
```

Имя файла:

```text
offonika_0.2.0.cfe
```

В расширении должны быть:

- основной язык `Language.Русский` из базовой конфигурации;
- HTTP-сервис `WBUnitEconomics`;
- шаблон `health`, метод `GET`, обработчик `HealthGet`;
- шаблон `mapping`, метод `GET`, обработчик `MappingGet`;
- роль `offonika_ТолькоЧтение`.

В расширении не должно быть:

- документов;
- справочников;
- регистров;
- констант;
- регламентных заданий;
- UI-форм;
- планов обмена;
- токенов, URL, паролей или клиентских параметров.

# Сборка `.cfe`

Сборка выполняется на машине, где установлен Конфигуратор 1С или 1C:EDT.

Порядок:

1. Открыть тестовую базу клиента или чистую совместимую базу с установленным
   `ИС_Маркетплейс`.
2. Импортировать или перенести безопасные исходники из
   `extensions/offonika/src/`.
3. Если импорт из XML недоступен, создать новое расширение
   `offonika` вручную и перенести из этого каталога:
   `Configuration.xml`, `HTTPServices/WBUnitEconomics.xml`,
   `HTTPServices/WBUnitEconomics/Ext/Module.bsl`,
   `Roles/offonika_ТолькоЧтение.xml` и
   `Roles/offonika_ТолькоЧтение/Ext/Rights.xml`.
4. Установить версию `0.2.0`.
5. Проверить, что в расширении есть только язык, HTTP-сервис и роль по spec.
6. Проверить синтаксис модулей.
7. Проверить, что в расширении нет объектов хранения данных и регламентных
   заданий.
8. Выгрузить расширение в `.cfe`.

Если при загрузке XML появляется предупреждение
`Неизвестный объект метаданных - InformationRegister.ИС_WB_...` или
`Catalog.ИС_WB_...`, не принимать такую загрузку для выпуска. Это означает, что
Конфигуратор не сопоставил права на объекты другого расширения при импорте XML.
Нужно использовать актуальный `Rights.xml`, где такие cross-extension references
не указаны, загрузить расширение заново, а эффективные read-only права на объекты
`ИС_Маркетплейс` настроить после загрузки в тестовой базе.

Файл `.cfe`, собранный под реального клиента, не помещать в Git и не прикладывать
к Markdown. Его передавать клиенту как рабочий артефакт отдельно.

Исходники в `extensions/offonika/` не содержат клиентских
данных, URL, паролей или токенов и предназначены для сборки в 1С/EDT.

# Установка у клиента

Рекомендуемый порядок:

1. Сделать резервную копию базы или проверить наличие актуального backup.
2. Установить `.cfe` сначала в тестовую базу.
3. Включить расширение.
4. Перезапустить сеанс 1С, если требуется.
5. Проверить health и mapping.
6. После приемки повторить установку в рабочей базе.

Что проверить в списке расширений:

```text
Имя: offonika
Версия: 0.2.0
Активно: да
Назначение: дополнение
```

# Публикация HTTP-сервиса

После установки расширения опубликовать HTTP-сервис:

```text
/hs/wb-unit-economics/v1/health
/hs/wb-unit-economics/v1/mapping
/hs/wb-unit-economics/v1/mapping?marketplace=ozon
```

Итоговый URL зависит от публикации базы:

```text
https://<host>/<base>/hs/wb-unit-economics/v1/health
https://<host>/<base>/hs/wb-unit-economics/v1/mapping
https://<host>/<base>/hs/wb-unit-economics/v1/mapping?marketplace=ozon
```

Методы должны быть только `GET`. Запись через HTTP-сервис не допускается.

# Пользователь и права

Создать отдельного пользователя:

```text
offonika_readonly
```

Выдать роль:

```text
offonika_ТолькоЧтение
```

Пользователь должен иметь только чтение:

- `РегистрСведений.ИС_WB_СоответствиеРазмеров`;
- `Справочник.ИС_WB_РазмерыНоменклатур`;
- `Справочник.ИС_WB_Номенклатура`;
- `РегистрСведений.ИС_WB_ШтрихкодыРазмеров`;
- `РегистрСведений.ИС_Ozon_СоответствиеХарактеристик`;
- `Справочник.ИС_Ozon_Номенклатура`;
- `Справочник.Номенклатура`;
- `Справочник.ХарактеристикиНоменклатуры`.

Если редактор роли `offonika_ТолькоЧтение` не показывает объекты
`ИС_Маркетплейс`, оставить в роли права на HTTP-сервис и стандартные справочники,
а пользователю дополнительно выдать существующую read-only роль клиента, которая
дает чтение объектов `ИС_Маркетплейс`. Не использовать роли с записью,
администрированием или изменением настроек обмена.

У пользователя не должно быть прав на:

- запись;
- проведение;
- удаление;
- изменение настроек обмена;
- чтение токенов WB/Ozon;
- чтение профилей API и настроек обмена Ozon;
- администрирование.

# Проверка после установки

Проверить health:

```bash
curl -u '<user>:<password>' \
  'https://<host>/<base>/hs/wb-unit-economics/v1/health'
```

Ожидаемый результат:

```json
{
  "schema_version": "1",
  "source": "1c_marketplace_http",
  "status": "ok",
  "generated_at": "2026-07-04T12:00:00+03:00",
  "marketplaces": ["wb", "ozon"]
}
```

Проверить маленькую выборку:

```bash
curl -u '<user>:<password>' \
  'https://<host>/<base>/hs/wb-unit-economics/v1/mapping?limit=10'

curl -u '<user>:<password>' \
  'https://<host>/<base>/hs/wb-unit-economics/v1/mapping?marketplace=ozon&limit=10'
```

В ответе WB должны быть только поля:

- `schema_version`;
- `source`;
- `marketplace`;
- `generated_at`;
- `timezone`;
- `row_count`;
- `truncated`;
- `rows`;
- внутри `rows`: `profile_key`, `nm_id`, `vendor_code`, `tech_size`,
  `wb_size`, `barcode`, `onec_item_id`, `onec_code`, `onec_article`,
  `onec_name`, `onec_characteristic_id`, `onec_characteristic`, `status`.

В ответе Ozon должны быть только поля:

- `schema_version`;
- `source`;
- `marketplace`;
- `generated_at`;
- `timezone`;
- `row_count`;
- `truncated`;
- `rows`;
- внутри `rows`: `marketplace`, `profile_key`, `ozon_item_id`, `product_id`,
  `ozon_name`, `offer_id`, `sku`, `sku_fbs`, `sku_fbo`, `barcode`,
  `onec_item_id`, `onec_code`, `onec_article`, `onec_name`,
  `onec_characteristic_id`, `onec_characteristic`, `package`, `status`.

Содержимое реального ответа `mapping` не отправлять в общий чат. Для проверки
нам достаточно `row_count`, списка полей и 1-2 обезличенных строк.

# Проверка безопасности

Перед подключением к проекту убедиться, что в ответе нет:

- `token`;
- `password`;
- `secret`;
- `apiKey`;
- `clientId`;
- `Authorization`;
- настроек профиля WB/Ozon;
- raw JSON от WB/Ozon;
- финансовых документов 1С.

Также проверить вручную, что пользователь `offonika_readonly` не может записать
или изменить объект 1С.

# Что передать в проект

Передать безопасные сведения:

```text
Тип доступа: 1С HTTP-сервис через расширение offonika
Версия расширения: 0.2.0
URL health: https://<host>/<base>/hs/wb-unit-economics/v1/health
URL mapping: https://<host>/<base>/hs/wb-unit-economics/v1/mapping
URL Ozon mapping: https://<host>/<base>/hs/wb-unit-economics/v1/mapping?marketplace=ozon
Пользователь: offonika_readonly
Пароль: передан отдельно безопасным способом
IP нашего сервера в белом списке: 102.129.178.65
```

Пароль, `.env`, полный mapping response и клиентские выгрузки не вставлять в
документы, Git или чат.

# Обновление расширения

При выпуске новой версии:

1. Поднять версию `.cfe`.
2. Обновить changelog.
3. Проверить контракт `schema_version`.
4. Установить сначала в тестовую базу.
5. Проверить `health` и `mapping?limit=10`.
6. Только после этого обновлять рабочую базу.

Если меняется состав JSON-полей не additive способом, сначала обновить
`docs/specs/onec-marketplace-mapping-http-service.md` и нормализатор проекта.

# Rollback

Для отката:

1. Отключить публикацию HTTP-сервиса.
2. Отключить пользователя `offonika_readonly`.
3. Деактивировать расширение в списке расширений 1С.
4. Если нужно, удалить расширение из тестовой/рабочей базы.
5. Вернуться к ручной TXT-выгрузке в `data/onec_marketplace_mapping/`.

Откат не должен удалять данные клиента в 1С, потому что расширение не создает
собственных таблиц и не пишет в базу.
