# Назначение

Этот runbook фиксирует, куда складывать локальные артефакты для сверки
юнит-экономики Wildberries с данными `1С:УНФ`.

Артефакты из этого процесса содержат клиентские данные и не должны попадать в
Git, Markdown-документы, общий чат или письма.

# Где хранить артефакты

- `data/onec_samples/<timestamp>/` — raw-снимки `1С:УНФ` из OData.
- `data/onec_manual_reports/<timestamp>/` — ручные Excel/CSV-выгрузки отчетов
  из интерфейса 1С для сверки с бухгалтерией.
- `data/wb_product_cards/<timestamp>/` — raw и flat-снимки карточек WB.
- `data/wb_finance/<timestamp>/` — raw-снимки финансового факта WB.
- `data/wb_documents/<timestamp>/` — raw metadata и скачанные ZIP/PDF
  первичных документов WB. В Git, Markdown и Excel переносить только metadata,
  hash, категорию и дату, без содержимого файлов.
- `reports/` — Excel-файлы для сверки и приемки.
- `config/` — только не-секретные настройки методики и связок, если они
  согласованы.

Реальные URL, логины, пароли и токены хранятся только в локальном `.env`.
Содержимое `.env` нельзя читать, копировать, выводить или переносить в
документацию.

# Минимальный сверочный пакет

Для встречи с бухгалтерией и ответственными за 1С нужны два Excel-файла:

1. Основной Excel MVP с листами `Сводка`, `Товары`, `Расходы WB`,
   `Себестоимость 1С`, `Маппинг`, `Ошибки данных` и `Методика`.
2. Отдельный reconciliation pack с листами:
   - `Сводка`;
   - `Вопросы бухгалтерии`;
   - `Missing mapping`;
   - `Ambiguous mapping`;
   - `Matched sample`;
   - `Себестоимость sample`.

Если доступен интерфейс 1С, дополнительно выгрузить из 1С ручной отчет
`Себестоимость остатков` с колонками `Количество`, `Сумма`, `Сумма без НДС` и
`Стоимость ед.`. Этот отчет нужен как эталон для сверки выбранного поля
себестоимости, но сам по себе показывает остатки, а не себестоимость уже
проданных на WB товаров.

Для себестоимости проданных товаров основной технический кандидат после
расширения OData — `AccumulationRegister_Продажи`, потому что он содержит
`Номенклатура_Key`, `Характеристика_Key`, `Организация_Key`, `Количество`,
`Сумма`, `СуммаНДС`, `Себестоимость` и `СебестоимостьБезНДС`.

# Что проверять

- есть ли пересечение штрихкодов WB и 1С;
- какие WB-штрихкоды отсутствуют в 1С;
- какие штрихкоды в 1С ведут к нескольким номенклатурам или характеристикам;
- какая организация 1С соответствует каждому WB-кабинету;
- отличаются ли налоговые настройки и учет НДС по организациям;
- включена ли в настройках 1С возможность `Себестоимость без НДС`, и как
  заполнен флаг `НДС включать в стоимость` в документах закупки/поступления;
- какое поле 1С считается правильной себестоимостью для отчета;
- совпадает ли выбранное поле с отчетом 1С `Себестоимость остатков`;
- что допрасходы уже включены в себестоимость 1С и не добавляются повторно;
- брать ли сумму с НДС или без НДС;
- на какую дату выбирать себестоимость для продажи и возврата.

# Команды

Выгрузить расширенный read-only sample из 1С:

```bash
.venv/bin/python scripts/export_onec_odata_samples.py --top 5000
```

Выгрузить read-only sample регистров для сверки валовой прибыли:

```bash
.venv/bin/python scripts/export_onec_odata_samples.py \
  --top 50 \
  --output-dir data/onec_gross_profit_samples/<timestamp> \
  --collection sales_register \
  --collection income_expense_register \
  --collection product_batches \
  --collection product_batches_usn \
  --collection product_batches_kudir
```

Собрать Excel MVP из последних локальных snapshots:

```bash
.venv/bin/python scripts/build_excel_mvp_from_snapshots.py
```

Собрать доказательный audit pack по одному контрольному `reportId` перед
изменением формул СПП/выручки:

```bash
.venv/bin/python scripts/build_wb_1c_audit_pack.py \
  --report-id <reportId> \
  --period-start 2026-06-09 \
  --period-end 2026-06-15 \
  --seller-account WB_ACCOUNT_1
```

Выгрузить read-only metadata первичных документов WB за период:

```bash
.venv/bin/python scripts/export_wb_documents.py \
  --period-start 2026-06-09 \
  --period-end 2026-06-15
```

Если бухгалтерии нужны сами первичные документы, добавить `--download`.
Файлы ZIP/PDF останутся в `data/wb_documents/<timestamp>/`, а manifest будет
содержать только metadata и hash.

Если отчет строится из конкретной 1С-выгрузки, явно указывать папку:

```bash
.venv/bin/python scripts/build_excel_mvp_from_snapshots.py \
  --onec-dir data/onec_samples/<timestamp>
```

Если доступен sample регистра `Продажи`, собрать отдельный отчет для сверки
себестоимости продаж:

```bash
.venv/bin/python scripts/build_excel_mvp_from_snapshots.py \
  --onec-dir data/onec_samples/<timestamp> \
  --sales-register-dir data/onec_gross_profit_samples/<timestamp> \
  --sales-cost-amount-field Себестоимость
```

`СебестоимостьБезНДС` использовать только для сверочного отчета, не как основной
расчет.

# Приемочные заметки

- `partial_source` в отчете означает неполный источник, а не нулевые продажи.
- `missing_mapping` означает, что WB-товар нельзя связать с 1С автоматически.
- `ambiguous_mapping` означает, что штрихкод найден в 1С, но имеет несколько
  возможных номенклатур или характеристик.
- Основная себестоимость берется из `AccumulationRegister_Продажи`, поле
  `Себестоимость`.
- Если налоговые настройки различаются по организациям, выбор поля себестоимости
  (`Сумма` или `СуммаБезНДС`) должен быть подтвержден отдельно для каждой
  организации или явно утвержден как единое правило для отчета.
- При включенной возможности `Себестоимость без НДС` ключевым становится флаг
  `НДС включать в стоимость` в документах: если он установлен, НДС включается в
  себестоимость поступивших ценностей; если нет, НДС отражается отдельно.
- Допрасходы уже распределены в себестоимость 1С; в отчете они не добавляются
  второй раз отдельным полем.
- Отчет, собранный из `AccumulationRegister_Продажи`, использует прямую
  себестоимость проданных товаров.
