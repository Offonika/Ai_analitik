# Контекст

Accepted implementation spec Excel MVP стал большим: в нем собраны источники,
формулы, листы Excel, команды и история изменений. Этот документ фиксирует
ключевые решения верхнего уровня, чтобы их было проще найти без чтения всего
spec.

# Решения

1. Основной артефакт приемки — стабильный Excel-файл
   `reports/shumeyko_wb_excel_mvp.xlsx`.
2. WB Finance detailed endpoint является источником товарного финансового факта.
   `sales-reports/list` используется как недельный контрольный свод и источник
   reportId, но не заменяет детализацию.
3. `deduction` и `deductionSum` относятся к отдельной статье `WB Продвижение`,
   а не смешиваются со штрафами.
4. Основная себестоимость текущего MVP берется из регистра 1С
   `AccumulationRegister_Продажи`, поле `Себестоимость`.
5. Если точной себестоимости за неделю продажи нет, можно использовать ближайшую
   доступную себестоимость, но строка получает статус
   `Себестоимость 1С требует сверки`.
6. Хранение WB и `WB Продвижение` распределяются по товарам так, чтобы итог
   сходился с недельным финансовым отчетом WB. Метод распределения виден на
   листе `Распределение расходов`.
7. НДС считается как включенный в цену: `net_revenue * 5 / 105`. УСН считается
   как `net_revenue * 1%`.
8. Прочие переменные расходы ОПиУ не уменьшают прибыль товара без отдельного
   принятого правила распределения.
9. Основной клиентский UX — `Дашборд`, `Юнит экономика`, `Возвраты`,
   `Ошибки данных`, `Методика`. Технические листы остаются в workbook, но
   скрываются по умолчанию.
10. `Ошибки данных` являются частью продукта, а не признаком поломанного отчета:
    partial source, missing mapping, missing cost и needs review должны быть
    явно видны.

# Следствия

- Нельзя считать товар надежно прибыльным без маппинга и себестоимости.
- Нельзя заменять ошибки WB API или rate limit нулевыми продажами.
- Нельзя отправлять клиенту отчет как финальный, если источник или период
  помечен как частичный.
- Новые расходы, новые источники и web-кабинет требуют отдельного accepted spec.
