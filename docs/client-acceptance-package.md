# Пакет приемки пилота AI-аналитика отчетов

Это шаблон состава и процедуры приемки. Он намеренно не содержит «текущий»
`report_id`, период или контрольные цифры: живое состояние определяется только
из расчетной БД по явно указанному идентификатору отчета.

## Как собрать пакет

```bash
PYTHONPATH=.:src .venv/bin/python scripts/build_client_acceptance_package.py \
  --report-id <report_id>
```

Пакет создается локально в `reports/client_packages/<report_id>/` и не попадает
в Git. Команда работает только на чтение с опубликованным отчетом и не меняет
Web API или БД.

Сборка завершается ошибкой, если отчет:

- отсутствует;
- не опубликован;
- имеет нефинальный статус;
- имеет readiness (готовность) не `ready` («готов»).

## Состав

- `acceptance-package.md` — читаемая карточка конкретной ревизии;
- `acceptance-package.docx` — та же карточка для передачи клиенту;
- `manifest.json` — безопасный реестр периода, покрытия источников, версии
  методики, готовности, агрегатных количеств и контрольных сумм артефактов.

Пакет не должен содержать raw data (исходные строки), токены, пароли, строки
подключения, URL с учетными данными или локальные пути к артефактам.

## Приемка конкретной ревизии

Перед передачей консультант сверяет:

1. период отчета и source coverage (покрытие источников) с кабинетом;
2. methodology version (версию методики) с Excel и web-кабинетом;
3. readiness (готовность): только `ready`;
4. агрегатные количества строк юнит-экономики, упущенных продаж и сверки
   документов;
5. SHA-256 каждого передаваемого артефакта с `manifest.json`;
6. отсутствие исходных клиентских строк и секретов.

## Значение статусов и терминов

- `source refresh` — обновление данных из источников только на чтение;
- `fallback` — резервный путь, используемый при недоступности основного;
- `readiness` — готовность конкретной ревизии к передаче клиенту;
- `baseline` — исторически зафиксированная контрольная ревизия, не синоним
  текущего отчета;
- `mapping` — сопоставление товара маркетплейса с номенклатурой 1С.

Статический документ не используется для поиска актуальной ревизии. Если нужен
другой отчет, команда запускается повторно с другим явным `--report-id`.
