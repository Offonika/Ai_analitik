# Пакет приемки пилота AI-аналитика отчетов

Документ фиксирует текущую клиентскую ревизию пилота Шумейко WB/1C для
приемки. Это не правило продукта на будущее: следующие отчеты создаются новым
`report_run` с выбранным `report_period`, отдельным `source_coverage` и своим
статусом готовности.

## Опубликованный baseline

- `report_run`: `excel_mvp_2026_03_01_2026_06_17`.
- `report_period`: `2026-03-01` — `2026-06-17`.
- `source_coverage`: `2026-03-01` — `2026-06-17`.
- Статус готовности клиентского пакета: `partial_period`.
- Причина статуса: июнь является неполным месяцем, данные есть по
  `2026-06-17`; отчет можно обсуждать как текущий baseline с явной оговоркой,
  но не как закрытый полный квартал.

## Артефакты приемки

- Excel MVP: `reports/shumeyko_wb_excel_mvp.xlsx`.
- DB-first HTML: `reports/db_first/excel_mvp_2026_03_01_2026_06_17_db_first.html`.
- DB-first DOCX: `reports/db_first/excel_mvp_2026_03_01_2026_06_17_db_first.docx`.
- DB-first PDF: `reports/db_first/excel_mvp_2026_03_01_2026_06_17_db_first.pdf`.
- DB-first CSV marts: `reports/db_first/csv/`.
- Фирменный аналитический черновик:
  `reports/Фирменный аналитический отчет Шумейко и Партнеры по юнит-экономике WB за период 01.03.2026-17.06.2026.md`.

Во всех клиентских артефактах должны быть видны отдельно:

- период отчета;
- покрытие источников;
- статус готовности.

## Что считает AI-аналитик

AI-аналитик отчетов работает поверх уже рассчитанных фактов и не меняет данные
WB/1C. В текущем пилоте он помогает подготовить черновик управленческого отчета
по:

- выручке, СПП, логистике, комиссиям, хранению, удержаниям и налогам;
- маржинальному доходу WB после налогов;
- товарам с отрицательным вкладом;
- возвратам и товарам с высокой долей возвратов;
- сверкам WB с 1С по документам, ОПиУ и расходам маркетплейса;
- предварительной витрине упущенных продаж по дням без остатка WB.

## Покрытые источники

- WB Finance / weekly financial reports за выбранный `report_period`.
- WB paid storage и WB promotion stats для распределения расходов.
- 1С:УНФ регистр продаж и данные валовой прибыли для себестоимости и сверки.
- 1С ОПиУ / income-expense register для сверки расходов.
- WB stock history и 1С остатки для предварительной витрины упущенных продаж.

## Ограничения

- Июнь неполный, поэтому динамику июня нельзя сравнивать с полным месяцем без
  нормализации или дозагрузки данных.
- Строки без подтвержденной себестоимости 1С и строки с вопросами маппинга
  остаются в отчете с явными статусами качества, а не заменяются нулями.
- Причины возвратов не передаются текущими источниками.
- Упущенные продажи являются управленческой оценкой для проверки, а не
  финальным прогнозом спроса.
- AI-черновик можно отдавать клиенту только после консультантской проверки
  формулировок и ограничений.

## Управленческие выводы для клиента

- Отчет можно использовать как первый baseline по юнит-экономике WB/1C за
  март-июнь 2026 с оговоркой о неполном июне.
- Отрицательные SKU, высокая логистика, возвраты и товары с днями без остатка
  являются первыми зонами управленческого разбора.
- Сверки с 1С показывают, где достаточно расчетной уверенности, а где нужны
  уточнение себестоимости, маппинга или документов.
- Для регулярного продукта следующий отчет должен выпускаться как новый
  `report_run`, а не как ручная правка существующего файла.

## Что дозагрузить или проверить

- Проверить строки `missing_cost`, `missing_mapping` и `ambiguous_mapping` в 1С
  и маппинге WB-1С.
- При необходимости дозагрузить полное покрытие за коммерческий период, который
  согласует клиент, например полный квартал или месяц.
- Проверить, что web-кабинет показывает тот же `report_period`,
  `source_coverage` и readiness status, что Excel и DB-first артефакты.
- Перед регулярным refresh настроить tenant integrations; если они отсутствуют,
  фиксировать `needs_configuration`, а не имитировать обновление.

## Acceptance checklist

- Excel README и лист `Дашборд` показывают период отчета, coverage и статус
  готовности отдельно.
- Web summary для `excel_mvp_2026_03_01_2026_06_17` показывает
  `reportPeriod = 01.03.2026 - 17.06.2026`,
  `sourceCoverage = 01.03.2026 - 17.06.2026`,
  `readiness.status = partial_period`.
- Markdown/DOCX/PDF-черновики показывают период отчета и coverage отдельно и не
  называют coverage периодом отчета.
- В активных acceptance-правилах нет безусловного запрета марта: строки
  исключаются только если они вне выбранного `report_period`.
- При неполном coverage отчет получает явный статус `source_coverage_gap`, а не
  выглядит `ready`.
