# Техническое задание на пилот AI-аналитика отчетов

## Юнит-экономика Wildberries по данным WB и 1С:УНФ

Заказчик: «Шумейко и партнеры».

Версия: draft для согласования с клиентом. Для реализации текущего Excel MVP
приоритет имеет accepted implementation spec.

Дата актуализации: 14 июля 2026.

Этот документ описывает клиентский Excel-пакет пилота. DB-first публикация
(публикация из расчетной БД), авторизованный web-кабинет и регулярный source
refresh (обновление данных из источников) являются внутренним контуром
подготовки и эксплуатации, если отдельный клиентский web-доступ не согласован.

# 1. Назначение проекта

Цель проекта — проверить пилот продукта `AI-аналитик отчетов` и подготовить для
заказчика «Шумейко и партнеры» понятный отчет по юнит-экономике продаж на
Wildberries.

Отчет должен показать, какие товары реально приносят прибыль, какие товары
убыточны или требуют проверки, и почему это происходит: из-за комиссии,
логистики, возвратов, себестоимости, удержаний, эквайринга или ошибок данных.

Решение не заменяет 1С, бухгалтерию, управленческий учет или решения
консультанта. Оно собирает данные из существующих источников, рассчитывает
показатели, помогает подготовить черновик клиентского анализа и быстрее
разобраться в результате.

# 2. Параметры пилота

В пилот входит:

- 1 клиент;
- 2 организации в 1С;
- 2 кабинета продавца Wildberries;
- период каждого отчета согласуется отдельно и фиксируется в `report_run`;
- покрытие источников WB/1С фиксируется отдельно; если данных не хватает на весь
  выбранный период, отчет получает явное ограничение;
- схема работы Wildberries: FBO и FBS;
- источник продаж и расходов: Wildberries Finance / Financial Reports;
- источник себестоимости: 1С:УНФ;
- себестоимость: с учетом дополнительных расходов;
- способ подключения к 1С: read-only OData или другой отдельно согласованный
  источник только на чтение; обезличенная выгрузка остается fallback
  (резервным путем);
- первый результат: Excel-отчет;
- дополнительный результат: опциональное ИИ-резюме и черновик клиентского
  аналитического отчета по рассчитанным данным.

Коммерческий период, например полный 2 квартал 2026 года, можно утвердить для
финальной приемки отдельно после загрузки WB и 1С за весь период. Это пример
согласованного периода, а не постоянное ограничение продукта. Если отчет
формируется до окончания согласованного периода или источники закрывают его
частично, он считается промежуточным.

# 3. Источники данных

Из Wildberries получаем:

- продажи;
- возвраты;
- комиссии;
- логистику;
- хранение;
- приемку;
- продвижение WB из финансового отчета WB;
- удержания;
- штрафы и доплаты;
- эквайринг;
- данные по товарам, нужные для сопоставления с 1С.

Основной источник финансового факта — WB Finance / Financial Reports.
Операционные отчеты и аналитика WB используются только как вспомогательные
источники после проверки актуальной документации WB.

Из 1С:УНФ получаем:

- организации;
- номенклатуру;
- артикулы;
- штрихкоды;
- характеристики товаров, если они используются;
- себестоимость с уже распределенными допрасходами;
- дату действия себестоимости;
- метод расчета себестоимости;
- поля для формирования кандидатов сопоставления товаров WB и 1С.

Подтвержденный mapping (сопоставление) хранится и изменяется только в
собственном сервисе проекта. Данные 1С и файлы не являются источником
окончательного решения, а импортируют кандидатов только на чтение.

Рекламные расходы не входят в первый Excel MVP и переносятся на следующий этап.

# 4. Подключение к 1С

Если 1С находится на облачном тарифе и поддержка не дает прямой доступ к серверу
СУБД, то прямое SQL-чтение базы недоступно. В этом случае для пилота используется
доступ через саму 1С: OData, HTTP-сервис 1С или регламентная выгрузка.

Если клиент переходит на индивидуальный сервер с полным доступом к SQL, можно
использовать прямое чтение базы 1С в режиме "только чтение".

В любом варианте сервис читает только нужные данные для отчета. Сервис не
записывает документы, не меняет себестоимость, не меняет справочники и не
выполняет операции в 1С.

Требования к подключению:

- отдельный технический пользователь без прав записи;
- доступ только к согласованным данным: организации, товары, артикулы, штрихкоды,
  характеристики, себестоимость и маппинг;
- для облака: OData, HTTP-сервис 1С или регламентная выгрузка;
- для индивидуального сервера: SQL-доступ только на чтение;
- подключение через защищенный канал или с ограничением по IP;
- запуск загрузки по согласованному расписанию;
- журнал подключений, загрузок и ошибок;
- предварительная проверка нагрузки на 1С.

1С остается источником себестоимости и учетных данных.

# 5. Сопоставление товаров Wildberries и 1С

Для расчета нужно связать товар Wildberries с товаром в 1С.

Сопоставление может выполняться по:

- штрихкоду;
- артикулу;
- коду товара;
- ручному правилу, если автоматическая связка недостаточна.

В MVP подтвержденный маппинг ведется в сервисе сопоставления проекта. 1С,
Wildberries и согласованные выгрузки используются как read-only источники
кандидатов: система предлагает возможные связи, а консультант подтверждает или
отклоняет спорные строки. Кабинет WB связывается с организацией 1С только через
явные стабильные идентификаторы `wb_cabinet_id` и `client_company_id`.
Автоматический выбор пары по порядку кабинетов и организаций запрещен. Несовпадение
организации строки отчета и организации кабинета является непереопределяемым
блокером публикации.

Если товар не удалось сопоставить надежно, он попадает в раздел ошибок данных.
Такой товар не должен считаться прибыльным или убыточным как точный факт, пока
связка не подтверждена.

# 6. Расчет юнит-экономики

Базовая логика расчета:

```text
Управленческая прибыль WB =
  выручка
  - комиссия Wildberries
  - логистика Wildberries
  - хранение Wildberries
  - приемка Wildberries
  - продвижение Wildberries
  - штрафы, удержания и доплаты Wildberries
  - эквайринг
  - себестоимость товара из 1С с уже распределенными допрасходами
```

В расходы Wildberries первого MVP входят:

- комиссия;
- логистика;
- хранение;
- платная приемка;
- продвижение WB из финансового отчета;
- удержания;
- штрафы и доплаты;
- эквайринг.

Реклама не входит в первый расчет. Если рекламные данные доступны, они
показываются как не включенные в MVP.

Налоговый слой считается только по подтвержденному профилю организации 1С. Для
ОСНО отдельно показываются `НДС к уплате`, применимые налоги на доход, кроме
НДФЛ предпринимателя, и `прибыль до НДФЛ`. В текущей методике ИП ОСНО
ненДФЛ-налог равен нулю, а НДФЛ по SKU не распределяется. Если профиль, ставка
или обязательный источник не подтверждены,
налоговые показатели остаются неопределенными и не заменяются нулями. Формула
`НДС 5/105 + УСН 1%` используется только для исторических legacy-отчетов с
явно зафиксированной старой версией методики.

Возвраты относятся к периоду WB Finance. Если известна дата исходной продажи, она
может храниться справочно.

Если расход нельзя надежно отнести к конкретному товару, он должен быть показан
отдельно.

# 7. Excel-отчет первого этапа

Первый результат — Excel-файл по пилотному клиенту и фактически загруженному
периоду WB Finance.

В отчете должны быть листы:

- `README` — клиент, период, статус периода, версия методики и ограничения;
- `Дашборд` — первый видимый лист с KPI, динамикой и проблемными товарами;
- `Сводка` — общий результат по периоду;
- `Сводка по организациям` — результат по двум организациям 1С;
- `Сводка по кабинетам WB` — результат по двум кабинетам WB;
- `Юнит экономика` — основной клиентский расчет по неделе, организации, кабинету и товару;
- `Ликвидность МД` — помесячная ликвидность маржинального дохода;
- `Товары` — расчет по каждому товару;
- `Динамика` — недельная динамика, неделя понедельник-воскресенье;
- `Сводный отчет WB` — недельные контрольные суммы WB;
- `WB поля отчета` — техническая расшифровка использованных полей WB;
- `Сверка по отчетам WB` — сверка расчетной витрины по reportId WB;
- `Сверка с 1С` — сверка с документами 1С;
- `Сверка документов 1С` — ручной контроль документов и количества;
- `Сверка с 1С ОПиУ` — контрольная сверка с 1С: основная помесячная
  себестоимость и количество сверяются по одинаковой выборке РВБ-документов
  и по дате документа 1С, расходы РВБ сверяются с ОПиУ;
- `Валовая прибыль 1С` — сверочный лист по регистру продаж 1С;
- `Сверка услуг WB` — сверка услуг WB с 1С;
- `Расшифровка услуг 1С` — строки УПД/поступлений услуг 1С;
- `Распределение расходов` — аудит распределения хранения и продвижения;
- `Товары по отчетам 1С` — товарная детализация внутри 1С-пакетов;
- `Расходы WB` — комиссии, логистика, хранение, приемка, удержания, эквайринг и
  другие расходы;
- `Возвраты` — влияние возвратов на результат;
- `Упущенные продажи` — оценка потерь из-за дней без остатка WB, если загружен
  исторический stock-report;
- `Себестоимость 1С` — использованная себестоимость с уже распределенными допрасходами;
- `Маппинг` — сопоставление Wildberries и 1С;
- `Ошибки данных` — товары без себестоимости, без связки или с неполными данными;
- `Методика` — формула расчета и принятые допущения;
- `ИИ-резюме` — опционально, если ИИ-блок включен после расчетной витрины.

Расчет должен выполняться сервисом, а не вручную внутри Excel. Excel используется
как понятный формат передачи и проверки результата.

По умолчанию клиент видит: `Дашборд`, `Юнит экономика`, `Ликвидность МД`,
`Динамика`, `Расходы WB`, `Возвраты`, `Упущенные продажи`,
`Сверка документов 1С`, `Сверка с 1С ОПиУ`, `Ошибки данных` и `Методика`.
Технические и прочие сверочные листы остаются в workbook, но скрываются от
основного клиентского UX.

# 8. AI-аналитик отчетов

AI-аналитик отчетов может быть добавлен в первый клиентский результат, но он не
блокирует приемку Excel MVP.

AI анализирует только рассчитанные и проверяемые данные. Он не меняет данные, не
принимает финансовые решения и не заменяет бухгалтера или консультанта.

Ожидаемый результат AI-блока:

- короткое резюме периода;
- проблемные товары и причины, подтвержденные расчетом;
- вопросы к данным, маппингу и себестоимости;
- черновик клиентского аналитического отчета для проверки консультантом.

Если источник не передает причину возврата, AI не должен придумывать ее в
клиентском тексте.

# 9. Веб-витрина после первого этапа

После проверки Excel-отчета рекомендуется сделать простой веб-кабинет
AI-аналитика отчетов.

Веб-кабинет — это не просто место для скачивания Excel. Клиент сможет открыть
отчет в браузере, выбрать период, отфильтровать товары и посмотреть показатели на
экране.

Excel остается дополнительным форматом для встречи, архива, отправки или ручной
проверки.

На следующих этапах web-кабинет может показывать свежесть источников, историю
отчетов, AI-черновики и регулярные digest по изменениям.

# 10. Что не входит в первый этап

В первый этап не входит:

- изменение цен, остатков или карточек на Wildberries;
- запись документов, справочников или себестоимости в 1С;
- подключение всех маркетплейсов;
- рекламная аналитика;
- самостоятельный клиентский web-доступ без отдельного согласования;
- production-хранение реальных клиентских данных;
- налоговый, юридический или бухгалтерский вывод вместо специалиста;
- автоматические финансовые решения.

# 11. Что нужно согласовать до старта

До начала работ нужно подтвердить:

- формат доступа к 1С;
- список данных 1С, которые разрешено читать;
- точные поля WB после проверки текущей документации и доступа по двум кабинетам;
- эталонные ручные цифры заказчика для финальной сверки методики;
- кто со стороны заказчика проверяет методику и принимает результат.
- кто проверяет и утверждает AI-черновик перед передачей клиенту.

# 12. Критерии приемки

Первый этап считается выполненным, если:

- загружены данные Wildberries по двум кабинетам продавца;
- получена себестоимость с уже распределенными допрасходами по двум организациям 1С;
- основные товары сопоставлены между Wildberries и 1С;
- сформирован Excel-отчет за согласованный период отчета;
- покрытие WB/1С источников видно в отчете, а неполное покрытие помечено
  отдельным статусом;
- в отчете есть расчет прибыли по товарам;
- эквайринг учтен в прибыли или отчет явно помечен как неполный;
- налоговый профиль и полнота налогового расчета видны явно; без профиля
  налоговые KPI остаются неопределенными;
- реклама не влияет на прибыль MVP;
- в отчете видны ошибки и неполные данные;
- формула расчета согласована с заказчиком;
- повторный расчет на тех же данных дает тот же результат;
- сервис не меняет данные в Wildberries и 1С.
