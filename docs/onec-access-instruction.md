# Короткая инструкция: доступ к данным 1С только на чтение

Для проекта юнит-экономики Wildberries нужен доступ к базе `1С:УНФ` только на
чтение. Доступ нужен, чтобы получить товары, артикулы, штрихкоды и себестоимость.

Сервис не должен ничего записывать в 1С.

# Если 1С в облаке

Если 1С находится на облачном тарифе и поддержка не дает прямой доступ к серверу
СУБД, то SQL-доступ использовать нельзя.

RDP-доступ к рабочему столу Windows Server сам по себе не означает, что есть
доступ к SQL-серверу. У провайдера может быть терминальный сервер, где пользователи
запускают 1С, а сервер СУБД остается закрытым. Поэтому нужно уточнить не "есть ли
RDP", а "есть ли доступ к SQL-серверу базы 1С".

В этом случае нужны варианты доступа через саму 1С:

- OData, если публикация OData доступна на тарифе;
- HTTP-сервис 1С, если его можно опубликовать;
- регламентная выгрузка из 1С в Excel, CSV или другой согласованный формат.

У поддержки 1С нужно спросить именно так:

```text
Можно ли на нашем облачном тарифе опубликовать OData или HTTP-сервис 1С:УНФ
только на чтение для справочника товаров, штрихкодов, характеристик и
себестоимости?

Если можно, пришлите, пожалуйста:
- URL публикации;
- способ авторизации;
- как создать отдельного пользователя только на чтение;
- можно ли ограничить доступ по IP 102.129.178.65.
```

Если поддержка отвечает, что прямой SQL доступен только на индивидуальном сервере,
то есть два пути:

- остаться на облачном тарифе и использовать OData/HTTP-сервис/выгрузку;
- перейти на индивидуальный сервер и дать SQL-доступ только на чтение.

# Как быстро понять, какой тип базы в 1С

На RDP-сервере можно открыть окно запуска 1С и посмотреть строку базы:

- если указан путь к файлу или папке, это файловая база;
- если указаны `Srvr` и `Ref`, это серверная база 1С через кластер;
- если есть отдельный доступ к MS SQL Server или PostgreSQL, администратор должен
  подтвердить адрес SQL-сервера, порт и возможность создать пользователя только на
  чтение.

Если в окне 1С виден только список баз без технических параметров, нужно спросить
поддержку One More Cloud:

```text
У нас есть RDP-доступ к терминальному серверу 1С. Подскажите, пожалуйста, где
размещена база 1С:УНФ: файловая база, серверная база через кластер 1С или SQL?

Есть ли на текущем тарифе доступ к SQL-серверу базы только на чтение?
Если SQL недоступен, можно ли опубликовать OData или HTTP-сервис 1С:УНФ только на
чтение для товаров, штрихкодов, характеристик и себестоимости?
```

# Важно: какие адреса нужны

Есть два разных адреса:

- `IP SQL-сервера клиента` — адрес сервера, где находится база 1С. Его клиент
  сообщает нам, чтобы наш сервис мог подключиться к базе.
- `IP нашего сервера` — адрес, с которого наш сервис будет подключаться к базе
  клиента. Его администратор клиента добавляет в firewall, VPN или белый список:
  `102.129.178.65`.

Схема подключения:

```text
наш сервер -> SQL-сервер клиента с базой 1С
```

API нашего сервиса и доступ к SQL-базе 1С — разные вещи. Для чтения себестоимости
нашему серверу нужен доступ к SQL-базе клиента. Веб-кабинет и наш API будут уже на
нашей стороне.

# Что нужно прислать, если доступ через OData или HTTP-сервис

Администратор 1С должен подготовить и передать:

- URL OData или HTTP-сервиса;
- имя пользователя только на чтение;
- пароль отдельным безопасным способом, не в общем письме;
- список опубликованных объектов или методов;
- можно ли ограничить доступ по IP нашего сервера: `102.129.178.65`;
- разрешенное время загрузки данных;
- контакт администратора.

Пример:

```text
Тип доступа: OData
URL: https://example.1cfresh.com/base/odata/standard.odata/
Пользователь: shumeyko_readonly
Пароль: передан отдельно
Доступ: только чтение
IP нашего сервера для белого списка: 102.129.178.65
```

# Минимальный состав публикации OData для пилота

Для первого Excel MVP через стандартный OData 1С нужно оставить только объекты,
которые нужны для товаров, маппинга, организаций, цен и себестоимости:

- `Catalog_Номенклатура`;
- `Catalog_Организации`;
- `Catalog_ХарактеристикиНоменклатуры`;
- `InformationRegister_ШтрихкодыНоменклатуры`;
- `InformationRegister_ЦеныНоменклатуры`;
- `AccumulationRegister_Запасы`;
- `AccumulationRegister_ЗапасыНаСкладах`.

`AccumulationRegister_Запасы` — главный кандидат для проверки себестоимости,
потому что в нем есть количество и суммовые поля. `AccumulationRegister_ЗапасыНаСкладах`
нужен в основном для сверки остатков и количества.

После sample-выгрузки важно смотреть вложенный `RecordSet` регистра `Запасы`, а
не только верхний уровень ответа OData. Для проверки себестоимости нужны поля
`Period`, `RecordType`, `Номенклатура_Key`, `Организация_Key`,
`Характеристика_Key`, `Количество`, `Сумма`, `СуммаБезНДС` и
`ФиксированнаяСтоимость`.

Планы обмена и прочие объекты, не нужные для расчета, лучше снять с публикации.
Если `AccumulationRegister_ПартииТоваров` нужен для партионной себестоимости, его
можно вернуть в публикацию отдельной проверкой, но на первом sample он не
обязателен.

Если в отчете 1С `Валовая прибыль по номенклатуре` видна себестоимость, для
сверки себестоимости именно проданных товаров нужно дополнительно опубликовать
read-only объекты:

- `AccumulationRegister_Продажи`;
- `AccumulationRegister_ДоходыИРасходы`;
- `AccumulationRegister_ПартииТоваров`;
- `AccumulationRegister_ПартииТоваровУСН`;
- `AccumulationRegister_ПартииТоваровДляКУДиР`.

`AccumulationRegister_Продажи` особенно важен, если он содержит поля
`Номенклатура_Key`, `Характеристика_Key`, `Организация_Key`, `Количество`,
`Сумма`, `СуммаНДС`, `Себестоимость` и `СебестоимостьБезНДС`.

Пользователь 1С должен иметь права только на чтение опубликованных объектов.
Запись, изменение, проведение документов и изменение справочников должны быть
запрещены.

# Sample-выгрузка для проверки формулы себестоимости

После настройки OData можно выгрузить маленький sample с нашего сервера:

```bash
.venv/bin/python scripts/export_onec_odata_samples.py --top 25
```

Для отдельной сверки валовой прибыли и себестоимости продаж выгрузить расширенный
sample регистров:

```bash
.venv/bin/python scripts/export_onec_odata_samples.py \
  --top 50 \
  --output-dir data/onec_gross_profit_samples/<timestamp> \
  --collection sales_register \
  --collection income_expense_register \
  --collection product_batches \
  --collection product_batches_usn \
  --collection product_batches_kudir
```

Скрипт делает только `GET`-запросы и сохраняет raw JSON локально в `data/`: для
обычной выгрузки в `data/onec_samples/`, для расширенной сверки в указанную
папку `data/onec_gross_profit_samples/`. В чат, документы и Git не нужно
переносить содержимое этих файлов: достаточно смотреть количество строк,
структуру полей и безопасные выводы по методике.

# Что нужно прислать, если доступ через SQL

Администратор SQL должен подготовить и передать:

- тип базы: `MS SQL Server` или `PostgreSQL`;
- IP-адрес или внутренний адрес SQL-сервера клиента;
- порт: обычно `1433` для MS SQL Server или `5432` для PostgreSQL;
- имя базы данных 1С;
- имя пользователя только на чтение;
- пароль отдельным безопасным способом, не в общем письме;
- куда добавить IP нашего сервера: firewall, VPN или белый список;
- разрешенное время загрузки данных;
- контакт администратора.

Пример:

```text
Тип базы: MS SQL Server
IP сервера: 10.10.10.25
Порт: 1433
База: UNF
Пользователь: shumeyko_readonly
Пароль: передан отдельно
Доступ: только чтение
IP нашего сервера для белого списка: 102.129.178.65
```

# Команда для MS SQL Server

Команду выполняет администратор базы из терминала, где доступен `sqlcmd`.

Вариант с SQL-администратором:

```bash
sqlcmd -S <SQL_SERVER_IP>,1433 -U <ADMIN_USER> -P '<ADMIN_PASSWORD>' -Q "CREATE LOGIN shumeyko_readonly WITH PASSWORD = '<STRONG_PASSWORD>'; USE [<DATABASE_NAME>]; CREATE USER shumeyko_readonly FOR LOGIN shumeyko_readonly; ALTER ROLE db_datareader ADD MEMBER shumeyko_readonly;"
```

Вариант с Windows-авторизацией:

```bash
sqlcmd -S <SQL_SERVER_IP>,1433 -E -Q "CREATE LOGIN shumeyko_readonly WITH PASSWORD = '<STRONG_PASSWORD>'; USE [<DATABASE_NAME>]; CREATE USER shumeyko_readonly FOR LOGIN shumeyko_readonly; ALTER ROLE db_datareader ADD MEMBER shumeyko_readonly;"
```

Что заменить:

- `<SQL_SERVER_IP>` — IP-адрес SQL-сервера;
- `<ADMIN_USER>` — администратор SQL Server;
- `<ADMIN_PASSWORD>` — пароль администратора;
- `<DATABASE_NAME>` — имя базы 1С;
- `<STRONG_PASSWORD>` — новый сложный пароль для пользователя
  `shumeyko_readonly`.

# Команда для PostgreSQL

Команду выполняет администратор базы из терминала, где доступен `psql`.

```bash
psql "host=<DB_SERVER_IP> port=5432 dbname=<DATABASE_NAME> user=<ADMIN_USER>" -c "CREATE USER shumeyko_readonly WITH PASSWORD '<STRONG_PASSWORD>'; GRANT CONNECT ON DATABASE <DATABASE_NAME> TO shumeyko_readonly; GRANT USAGE ON SCHEMA public TO shumeyko_readonly; GRANT SELECT ON ALL TABLES IN SCHEMA public TO shumeyko_readonly; ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO shumeyko_readonly;"
```

Что заменить:

- `<DB_SERVER_IP>` — IP-адрес SQL-сервера;
- `<DATABASE_NAME>` — имя базы 1С;
- `<ADMIN_USER>` — администратор PostgreSQL;
- `<STRONG_PASSWORD>` — новый сложный пароль для пользователя
  `shumeyko_readonly`.

# Что важно

- Пользователь должен быть отдельный: `shumeyko_readonly`.
- У пользователя не должно быть прав записи.
- Нельзя выдавать администратора 1С или SQL.
- Лучше разрешить подключение только с IP нашего сервера или через VPN.
- Пароль не отправлять в общем чате, письме или документе.
- Перед регулярной загрузкой проверить, что пользователь не может менять данные.

# Проверка после создания пользователя

Нужно проверить:

- подключение к базе работает;
- чтение данных работает;
- запись, изменение и удаление данных запрещены;
- запросы не мешают работе 1С.

# Текст для отправки администратору

Нужно предоставить доступ к данным `1С:УНФ` только на чтение для проекта
юнит-экономики Wildberries. Если прямой SQL на облачном тарифе недоступен,
подойдет OData, HTTP-сервис 1С или регламентная выгрузка. Нужны товары, артикулы,
штрихкоды, характеристики и себестоимость. Запись в 1С, изменение документов,
справочников и себестоимости не требуются и должны быть запрещены. IP нашего
сервера для белого списка: `102.129.178.65`.
